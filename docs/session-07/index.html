    S07 · P03Why it matters⏱ 4 min

    Why Malware Is the Center of Gravity

    Nearly every breach ends in malware doing the work — stealing, encrypting, spying, or spreading.

    The one skill that pays off everywhere

    Ransomware, data theft, espionage, botnets — the initial access varies, but the payload is where the damage happens. Understanding malware behaviour is the shared core of SOC triage, incident response, threat hunting, and detection engineering.

    The mindset

    Detect the behaviour, not the file. Names and hashes change weekly; what a type does — and the evidence that leaves — is durable. That is what this session trains.

    S07 · P04Foundations · classify⏱ 8 min

    How to Classify Any Sample

    Two questions place any malware: how does it spread, and what does it do? Most samples are hybrids of both.

    Two axes, not one list

    CEH lists a handful of types; the real world tags every sample on two independent axes. Propagation is the verb (how it arrives/spreads); purpose is the noun (what it does once running). One file is often several things — “a fileless infostealer dropped by a malicious macro.”

    Why this matters for detection

    Propagation tells you how it got in; purpose tells you what to hunt. A worm needs network containment; a stealer needs credential and egress monitoring. Two axes → two detection strategies.

    S07 · P06Foundations · families⏱ 6 min

    Families, Variants & the Naming Mess

    Samples that share a codebase form a family; match a new one to a known family and you inherit its whole playbook.

    Family = shared origin

    A family is a group of samples from the same codebase/crew (Emotet, LockBit, RedLine). Each sample is a variant. Match a sample to a family and you instantly inherit its signatures, IOCs, TTPs, and likely next move.

    Notable families to know

    FamilyClassAlso known asWhy it’s notable

    TrickBotBanking trojan / loader—Often paired with Emotet → Ryuk ransomware
    QakBot (Qbot)Banking trojan / loaderPinkslipbotLong-lived; macro delivery; drops ransomware
    RedLine / Lumma / VidarInfostealers—Dominant credential & cookie theft, 2023–25

    njRAT / QuasarRATsBladabindi (njRAT)Common crimeware & training samples

    Names vary by vendor — cross-reference each family on Malpedia, MITRE ATT&CK Software and abuse.ch.

    Finding variants: fuzzy hashing

    MD5/SHA change completely if one byte changes — useless for “is this a variant?”. ssdeep, TLSH (fuzzy hashes) and imphash (import-table hash) stay similar across variants, so they cluster a family together.

    The naming problem

    There is no single global name. Microsoft, Kaspersky, and CrowdStrike each name a family from their own telemetry, so one malware has many names. Pivot on shared hubs: Malpedia, MITRE ATT&CK Software, abuse.ch.

    Before you analyse it, know its anatomy. Windows malware is almost always a PE — and its imports betray its intent.

    Imports betray intent

    S07 · P08Foundations · internals⏱ 7 min

    Packing, Crypters & Obfuscation

    Real samples rarely look like clean code. They are compressed, encrypted, and obfuscated on purpose — to beat you.

    Three layers of hiding

    Packer = compresses the exe; a tiny stub unpacks it into memory at runtime (UPX). Crypter = encrypts the payload to beat AV, decrypts in memory. Protector = anti-debug / anti-VM / virtualization (VMProtect, Themida). Often stacked together (“FUD” = fully undetectable).

    UPX0 · stub2.4 MB → 0.6 MB
    strings: 3 · imports: 2 — squeezed & hidden
    normA normal program — readable code, 148 imports, 2.4 MB.

    • A packer compresses it into a small file — 2.4 MB → 0.6 MB.
    • On disk now: almost no strings or imports — you can’t read it.
    • At runtime a tiny stub unpacks the real code back into memory.
    • High entropy + odd sections (UPX0) = packed. Unpack it to analyze.

    Obfuscation you will meet

    String encryption (recover with FLOSS), control-flow flattening, junk code, API hashing (empty IAT), base64/XOR encoding, and .NET obfuscation (clean with de4dot). Detect packers with DIE (Detect It Easy); unpack with upx -d or a memory dump in x64dbg.

    S07 · P09Foundations · internals⏱ 5 min

    The Languages Malware Is Written In

    Language choice is itself an evasion decision — and it decides how hard the sample is to reverse.

    From easy to brutal to reverse

    .NET (C#/VB) — njRAT, Agent Tesla, Quasar; decompiles almost to source with dnSpy. C/C++ — native, classic; reverse in Ghidra/IDA. Scripting (PowerShell/VBA/JS) — fileless delivery. Go / Rust / Nim — cross-platform, big stripped binaries, chosen to slow reversers and dodge signatures (BlackCat/ALPHV is Rust).

    Languages — most common in malware first

    LanguageIn simple wordsWhy malware authors pick it
    C / C++The classic language that talks straight to the computer — fast and small.Full control of Windows; the old-school, most common choice.
    .NET (C# / VB)Microsoft’s easy, quick-to-build language.Tons of ready-made RATs & stealers (njRAT, Agent Tesla) — but the easiest for analysts to read back to near-source.
    Scripting (PowerShell / VBScript / JS)Small text scripts that run without installing anything.Perfect for the first step of an attack and for fileless malware that lives in memory.
    PythonA simple, very popular, beginner-friendly language.Quick to write; bundled into an .exe. Common in tools and some loaders.
    DelphiAn older desktop language.Still shows up in packers and loaders; its odd output slows reversers.
    AutoItA tiny automation language for simple tasks.Fast to make small droppers; easy to obfuscate.
    Go (Golang)A modern language that builds one program for Windows, Linux and Mac.Cross-platform reach; big files that are harder to take apart. Rising fast.
    RustA very modern, memory-safe language.Very hard to reverse — newer ransomware like BlackCat/ALPHV uses it.
    NimAn unusual, little-known language.Chosen mainly because few tools expect it — helps dodge antivirus.

    Rough order by how often it is seen in real malware — the top rows are the most common; Go / Rust / Nim are the fast-growing “exotic” choices.

    Read the language as a clue

    A .NET stealer decompiles in minutes; a Rust ransomware fights you for days. The “exotic language” trend (Go/Rust/Nim) is deliberate evasion — expect more of it.

    S07 · P10Foundations · method⏱ 7 min

    The 4-Stage Analysis Pyramid

    Not just “static vs dynamic.” Cheap and fast at the bottom, deep and slow at the top — climb only as high as the case needs.

    The rule

    Static says what it is; dynamic proves what it does; packing forces the truth out at runtime; memory catches what never touched disk.

    S07 · P11Method · static⏱ 7 min

    Static Analysis — Look Without Running

    Safe, fast, first. Identity and reputation, then what the file carries.

    Two moves

    Identity & reputation: hash it (SHA-256), look it up on VirusTotal / MalwareBazaar, fuzzy-hash for family. What it carries: strings / FLOSS (URLs, IPs, commands, ransom notes), packer check (DIE), and PE imports (capability from the IAT).

    ▶ Prove it — imports reveal purpose
    # A downloader gives itself away in its imports:
strings sample.exe | grep -i "urldownloadtofile\|winhttp\|internetopen"
# PEStudio / pefile show the full IAT — behaviour before you ever run it.
    Analyst toolkit — static
    VirusTotalmulti-engine verdict
    PEStudioPE header & imports
    strings / FLOSSreadable + hidden strings
    DIEpacker & entropy
    S07 · P12Method · dynamic⏱ 7 min

    Dynamic Analysis — Detonate & Watch

    Run it in an isolated sandbox and watch four behaviour channels.

    The four channels

    Processes (children, injection) · File system (drops, encryption) · Registry (Run keys, services = persistence) · Network (C2 beacon, DNS, downloads). Tools: Process Hacker, ProcMon, Regshot, TCPView, Wireshark; fake the internet with INetSim / FakeNet-NG.

    Automated & interactive sandboxes

    ANY.RUN (interactive), Hybrid Analysis, Triage, CAPE/Cuckoo, Joe Sandbox — detonate at scale, get a process tree, IOCs, and ATT&CK mapping in minutes.

    Analyst toolkit — dynamic
    ProcMonfile/registry/process
    Wiresharknetwork capture
    TCPViewlive connections
    ANY.RUNinteractive sandbox
    S07 · P13Method · advanced⏱ 6 min

    Advanced Static & Memory Forensics

    When packing and fileless malware beat the basics, go deeper.

    Reverse & remember

    Advanced static = disassemble/decompile in Ghidra / IDA to read the true logic (imports, strings, control-flow, process-injection routines). Advanced dynamic = a debugger (x64dbg) to dump the unpacked code from memory, plus memory forensics (Volatility 3) to find injected / fileless code that never hit disk.

    Why memory is mandatory

    You cannot hash what is not on disk. Fileless malware lives in RAM — memory analysis is the only place it shows up in full.

    Analyst toolkit — advanced
    Ghidradisassemble / decompile
    x64dbgdebug & unpack
    dnSpy.NET to source
    Volatility 3memory forensics
    S07 · P14Method · safety⏱ 5 min

    The Safe Lab — Rules Before We Detonate

    Everything after this page runs real samples. These rules are non-negotiable.

    ⚠ Read this before every detonation
    • Isolated VM only (Windows 7 analysis VM), host-only / no internet — fake C2 with INetSim / FakeNet-NG.
    • Clean snapshot before, revert after — one snapshot per sample.
    • Source samples only from research repos (MalwareBazaar / abuse.ch). Never email, upload, or run outside the lab. Delete at session end.
    • Wipers and ransomware destroy the VM — that is expected; the snapshot is your undo.
    • For Linux/IoT, Android, destructive, or fileless samples, prefer ANY.RUN (cloud) — no risk to the local lab.
    The habit

    Snapshot → isolate → detonate → observe → revert. Every type section that follows assumes this discipline.

    S07 · P15Type · extortion⏱ 9 min

    Ransomware

    Locks your files, then sells them back. Modern crews steal the data first and destroy your backups — so paying feels like the only way out.

    Propagation: trojan / wormPurpose: extortion (encrypt + steal)
    Concept

    Ransomware is malware with a revenue model: encrypt what the victim needs, sell the key back, and — in modern “double extortion” — also leak the stolen copy. It arrives via trojan/worm, escalates (S6), kills recovery, then encrypts fast. The speed and the recovery-kill are exactly what a defender can catch.

    Old ransomware
    • Encrypts local files, drops a note, asks for coins
    • Opportunistic, single machine
    • Backups = clean recovery
    Modern ransomware
    • Steals data first — double / triple extortion
    • Hunts & deletes backups + shadow copies + cloud sync
    • Dwell days–weeks; RaaS affiliate model

    S07 · P16Type · remote control⏱ 8 min

    Trojans & RATs

    A disguised program that hands the attacker a live remote console — files, keystrokes, even the webcam.

    Propagation: trojanPurpose: remote access (RAT) / backdoor
    Concept

    A trojan looks legitimate so the user runs it willingly. A RAT (Remote Access Trojan) is a trojan whose payload is full remote control. The victim dials out to the attacker’s C2 — which is exactly how it beats inbound firewalls, and exactly where egress monitoring catches it.

    Old RAT
    • Single operator, noisy plaintext C2
    • Strings reveal host/port/mutex
    Modern RAT
    • Encrypted C2, modular plugins, sold as MaaS
    • Blends via Discord / Telegram / GitHub as C2

    S07 · P17Type · resource theft⏱ 6 min

    Cryptominers (Cryptojacking)

    Steals your CPU/GPU to mine cryptocurrency. The loudest, easiest malware to see — just open Task Manager.

    Propagation: trojan / worm / drive-byPurpose: resource theft (mining)
    Concept

    A miner (usually XMRig-based) runs quietly and burns your processor to mine Monero for the attacker. The tell is obvious: sustained near-100% CPU by a process that should be idle, and a connection to a mining pool.

    Old miner
    • Obvious 100% CPU, easy to spot
    Modern miner
    • Throttles / pauses when Task Manager opens to hide
    • Targets servers & cloud; worm-like spread

    S07 · P18Type · credential theft⏱ 7 min

    Grabs saved passwords, cookies, and wallets in seconds and ships them out. The dominant crimeware of 2024–25.

    Old stealer
    • Grabs saved passwords, emails them out
    Modern stealer
    • Steals session cookies / tokens to bypass MFA

    S07 · P19Type · self-replication⏱ 7 min

    Viruses & Worms

    Both self-replicate. The difference is one word: a virus needs a click, a worm does not — and that word decides whether you get an incident or an outbreak.

    Propagation: virus (needs a click) / worm (self-spread)Purpose: varies (often carries a payload)
    Concept

    S07 · P28Detect · the SOC flip⏱ 9 min

    From Analysis to Detection

    Every behaviour you watched has a detection. Turn indicators into rules — and climb the Pyramid of Pain.

    IOCs come in three layers

    Host (hash, filename, Run key, mutex, task) · Network (C2 domain/IP, URL, JA3) · Behavioural (process injection, encoded PowerShell, mass file rewrite). The behavioural layer is the durable one.

    Map behaviour to ATT&CK

    Persistence T1547.001 (Run key) · Injection T1055 · PowerShell T1059.001 · Cred stores T1555 · C2 T1071 · Encrypt for impact T1486 · Inhibit recovery T1490 · Resource hijack T1496 · Disk wipe T1561.

    ▶ YARA — a rule for the file
    rule Example_Loader {
  meta: author = "SOC"
  strings:
    $s1 = "URLDownloadToFileA"
    $s2 = "\\AppData\\Roaming\\svc.exe" ascii
  condition:
    uint16(0) == 0x5A4D and all of ($s*)   // MZ + both strings
}
    ▶ Sigma — a rule for the behaviour (in logs)
    title: Office spawns encoded PowerShell
logsource: { product: windows, category: process_creation }
detection:
  sel:
    ParentImage|endswith: ['\WINWORD.EXE','\EXCEL.EXE']
    Image|endswith: '\powershell.exe'
    CommandLine|contains: '-enc'
  condition: sel
level: high
    The SOC flip

    YARA answers “is this file/memory malicious?”; Sigma answers “did this behaviour happen in my logs?” You write both from one analysis.

    S07 · P29Defend⏱ 5 min

    Countermeasures — Break the Chain

    Map each defence to the lifecycle stage it stops. Defence in depth = break the chain in more than one place.

    By lifecycle stage

    Delivery: mail filtering, attachment sandboxing, disable macros, web filtering. Execution: app allow-listing / WDAC, block LOLBins, user awareness. Persistence: monitor Run keys / tasks / services with EDR. C2: egress filtering, DNS monitoring, block known C2. Actions: offline backups (ransomware), DLP, network segmentation.

    Detect the behaviour, keep offline backups, segment the network, and log process command lines. These beat whole classes of malware regardless of family or name.

    4. Map to MITRE ATT&CK — give every behaviour a technique ID.
    5. Write the detections — one YARA rule (file) + one Sigma rule (behaviour).

    S07 · P32Quiz⏱ 10 min

    Knowledge Check

    Six questions across the whole session. Answer before you reveal.

    Q1How do analysts classify any malware sample?

    • By file size
    • By the AV vendor name only
    • On two axes — propagation × purpose
    • By the programming language

    Q2A PE shows entropy ~7.9 and almost no imports. What does that mean?

    • It is benign
    • It is packed / encrypted — pivot to dynamic + memory
    • It is a document
    • It is a rootkit

    Q3Why is a rule on ‘vssadmin delete shadows’ so valuable against ransomware?

    • It runs before encryption — catching it can save the data
    • It is the encryption command
    • It only appears in wipers
    • It is the ransom-note name

    Q4Why does fileless malware defeat file-signature AV?

    • It is encrypted
    • It is written in Rust
    • It is a virus
    • There is no file on disk — it runs in memory via LOLBins

    Q5Which indicator gives the most durable detection?

    • The exact file hash
    • The C2 IP address
    • The behaviour / TTP
    • The dropped filename

    Q6What separates a wiper from ransomware?

    • A wiper is slower
    • A wiper destroys data with no key / no recovery
    • A wiper only hits Linux
    • A wiper needs a click
    Score yourself

    S07 · P33Wrap-up⏱ 4 min

    Session 7 — What You Keep

    Malware changes weekly; this workflow does not.

    1. Classify by behaviour, not by name. Propagation × purpose places any sample.
    2. One lifecycle fits all. Delivery → execution → persistence → C2 → actions — each leaves evidence.
    3. The file fights you. Packing, crypters, obfuscation, exotic languages — high entropy + empty imports = pivot to dynamic + memory.
    4. Climb the pyramid. Cheap triage first; deep reversing only when needed.
    5. Every type has a tell. vssadmin (ransomware), 100% CPU (miner), SMTP exfil (stealer), Office→PowerShell (delivery), signed-tool abuse (fileless).
    6. You cannot hash what is not on disk. Fileless/LOLBins force behavioural detection.
    7. Analysis is detection engineering. YARA for the file, Sigma for the behaviour, a report that ships both.
    8. Block the hash today; detect the TTP forever.
