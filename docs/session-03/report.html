A · Setup & scope — do this first

Scope & authorization checkconfirm scanning is allowed — before any packet
Example — the line that authorises a scan
In scope:      203.0.113.0/24, *.target.com
Out of scope:  shared/hosted assets
Testing:       port scanning ALLOWED, max 5 req/s, no DoS
Window:        any time, identify with X-Bug-Hunter header
Collect
  • That active scanning is explicitly allowed, and the rate limit
  • The in-scope IP ranges / hosts (scan nothing else)
  • Any forbidden test types (DoS, brute-force) and required test window
Why it matters later: a port scan is the first thing that reaches the target and the first thing its IDS logs. Everything below is active — outside an authorised scope it is an attack, not a test.

B · Host discovery & port scanning — packets to the target

Live-host discoverynmap -sn 203.0.113.0/24 -oA sweep
Example output
Nmap scan report for 203.0.113.10  Host is up (0.011s)
Nmap scan report for 203.0.113.20  Host is up (0.009s)
Nmap done: 256 hosts, 4 up
Collect
  • Which of your Session 2 hosts are actually up
  • New live IPs in-scope you did not have from recon
Why it matters later: you only scan live hosts — this trims the range so the loud full scan hits real targets, not dead space.
Full TCP port scan (SYN)nmap -sS -p- --min-rate 2000 -Pn 203.0.113.20 -oA allports
Example output
PORT     STATE SERVICE
22/tcp   open  ssh
80/tcp   open  http
443/tcp  open  https
3389/tcp open  ms-wbt-server
8080/tcp open  http-proxy
Collect
  • Every open TCP port per host (all 65535, not just top 1000)
  • Note the odd/high ports — they are where the interesting services hide
Why it matters later: this open-port list is the map for the rest of the session; each port becomes a service you enumerate in C, and a lead you rank in D.
Service & version detectionnmap -sV -sC -p22,80,443,3389,8080 203.0.113.20 -oA services
Example output
22/tcp   OpenSSH 7.4 (protocol 2.0)
80/tcp   Apache httpd 2.4.29 ((Ubuntu))
8080/tcp Apache Tomcat 8.5.31
|_http-title: Staging Portal
Collect
  • Service + exact version on every open port
  • Default-script findings (titles, certs, anonymous access)
Why it matters later: the version string is the whole game for Session 4 — Tomcat 8.5.31 maps straight to a CVE. Vague "http" is useless; "Apache 2.4.29" is a lead.
OS detectionnmap -O 203.0.113.20
Example output
Running: Linux 4.X
OS CPE: cpe:/o:linux:linux_kernel:4.15
OS details: Linux 4.15 - 5.6
Collect
  • Best-guess OS and version per host
  • Whether it is Windows vs Linux — it changes every enumeration tool in C
Why it matters later: OS decides your toolset: SMB/LDAP for Windows, NFS/SSH for Linux — and Windows version hints at MS17-010-class exposure.
UDP top portsnmap -sU --top-ports 20 203.0.113.20
Example output
PORT    STATE         SERVICE
53/udp  open          domain
161/udp open          snmp   ← enumerate this
500/udp open|filtered isakmp
Collect
  • Open UDP services — especially 161 (SNMP), 53, 123, 500
  • TCP-only scans miss these entirely
Why it matters later: SNMP on 161 is a goldmine you enumerate in C3, and it is invisible to every TCP scan — this is the step teams forget.

C · Enumeration — turn each service into detail

Web (80/443/8080)whatweb https://203.0.113.20 ; nmap --script http-enum -p80,443,8080 203.0.113.20
Example output
HTTP/1.1 200  Apache/2.4.29  PHP/7.2
/admin/    (Status: 401)
/backup/   (Status: 200)
/robots.txt (Status: 200)
Collect
  • Server, framework, CMS + versions; directories & admin panels
  • robots.txt, default pages, exposed backups
Why it matters later: feeds Session 8 web testing and Session 4 login targets; the version confirms your CVE leads from B3.
SMB (139/445)enum4linux-ng -A 203.0.113.20 ; nmap --script "smb-os-discovery,smb-enum-shares,smb-enum-users" -p445 203.0.113.20
Example output
OS: Windows Server 2019
Shares: ADMIN$, C$, IPC$, Backups (READ)
Users: administrator, svc_backup, m.said
[note] modern Windows: null session refused
Collect
  • Shares (readable ones especially), users, OS build, domain
  • Whether null/guest sessions work (legacy) or are refused (modern)
Why it matters later: usernames feed Session 4 spraying/Kerberoast; a readable share can hold creds; the modern-vs-legacy result tells you which attacks are even possible.
SNMP (161/udp)onesixtyone 203.0.113.20 public ; snmpwalk -v2c -c public 203.0.113.20
Example output
public   → community string valid
sysDescr: Linux target 4.15
hrSWRunName: /usr/sbin/sshd, mysqld, apache2
installed software, listening ports, user accounts…
Collect
  • A valid community string (try public/private/community)
  • Running processes, software, ports, user accounts, ARP tables
Why it matters later: a weak SNMP community string leaks the whole host inventory without a login — one of the fastest wins on the exam and in the field.
LDAP / Active Directory (389/636)nmap --script ldap-rootdse -p389 dc.ceh.lab ; ldapsearch -x -H ldap://dc.ceh.lab -b "dc=ceh,dc=lab"
Example output
namingContext: DC=ceh,DC=lab
CN=Administrator,CN=Users,DC=ceh,DC=lab
CN=svc_sql,...  servicePrincipalName: MSSQL/...
sAMAccountName: m.said, a.hassan
Collect
  • The domain naming context, users, groups
  • Accounts with a servicePrincipalName (SPN) — Kerberoast targets
Why it matters later: this is the Session 4 attack surface: the user list is your spray list, and any SPN account is a Kerberoasting target.
Other services (FTP/NFS/SMTP/RPC)showmount -e 203.0.113.30 ; smtp-user-enum -M VRFY -U users.txt -t 203.0.113.30 ; ftp 203.0.113.30
Example output
NFS: /home *  (world-readable export!)
SMTP: 252 a.hassan (user exists)
FTP: anonymous login ALLOWED
Collect
  • Anonymous FTP, exported NFS shares, SMTP user enumeration
  • Any service that answers without a credential
Why it matters later: a world-readable NFS export or anonymous FTP is often a direct foothold, and SMTP VRFY confirms which usernames are real before you spray them.
